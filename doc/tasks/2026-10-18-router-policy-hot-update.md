## 二、总体架构

历史基线 v0.4.76：control.refresh 比较整份快照，置 e->refresh 并退出控制线程；engine 退出后销毁全部载体、NAT、监听和 TUN。普通 Probe 使用运行配置差异保留健康链路。
目标：控制线程下载、校验、保存并投递待应用快照，继续控制流。引擎主线程在握手空闲点消费，比较基础参数，增量更新固定槽位和策略；仅基础变更向 service 交接完整重建。e->mutex 保护跨线程策略读取和发布，网络请求在锁外执行，版本代号拒绝旧请求结果。
追加设计：普通 CIDR 使用只匹配 LAN 入站的独立策略表，TUN 回注和插件自身套接字走主路由表。SNI 使用 LAN TCP/443 REDIRECT 到本地有界透明 TCP 处理器，先读取 ClientHello 再建上游；远程 TCP 沿用 Probe main=8 的会话协议，不能在已经建立的 TCP 包路径上强行切换出口。原 Fake IP 数据面继续使用。

追加延迟修复架构：载体改为按完整 WebSocket 帧的三条有界链表，control 预留 32 KiB、bulk 上限 96 KiB、合计内存不超过原 256 KiB；控制优先，业务每 8 帧允许一帧测速。main=8 整个会话生命周期走同一业务 FIFO，测速 start/data/finish 同走 bulk，避免跨队列关闭乱序。正在 SSL_write 的帧不被抢占，单次最多 16 KiB，WANT 重试保持地址和长度。仅载体套接字尝试 TCP_NOTSENT_LOWAT=16 KiB（内核不支持时兼容回退）；不降低 TCP 窗口，不修改认证。

## 七、决策与冲突记录

DEC-001：网络 IO 不放进策略发布锁；主线程等待已发起握手完成后再交换其借用的快照，等待期间继续转发；不直接取消全部握手和健康链路。
DEC-002：Probe linux_router 的现有 SNI 是观察和 reject，不会在 ClientHello 后切换已建立 TCP 的出口；插件新增透明 TCP 入口和现有代理协议实现完整选择出口。
DEC-003：按用户“不要影响正常连接”约束，SNI 默认关闭（替代此前 IF-002 默认开启设计），既有 NAT TCP 会话固定目标与出口，新 SYN 应用当前规则；上线时不批量改生产开关。
DEC-004：不搬迁已建流，不将 main=8 close 提升到数据之前；分类调度只能在完整 WebSocket 帧边界抢占。TCP_NOTSENT_LOWAT 仅限制未发送数据，不缩小已发送未确认窗口。
冲突：无。发布技能旧的 Docker/arm64 路由附件标记与当前实际 workflow 不一致，沿用前任务已验证的实际工作流合同，不恢复已删除产品。

## 八、缺陷记录

DEF-001：高；控制刷新对任何实际 JSON 变化完整退出引擎，导致全部物理槽位重连；已修复，真实控制流和 15 项载体互操作验证通过。
DEF-002：高；新增路由差异函数在首次加载时对 NULL 旧规则调用 json_object_array_length；内核首次启动测试发现，已加空策略保护。最终 native/ARM 附件已重建，真实内核及全部互操作验证通过。

DEF-004：中；单 FIFO 无控制容量预留且一次 SSL_write 可覆盖整队列，负载会放大控制响应等待；已现场抓到插件 262088 bytes 和内核 525696 bytes 积压，已修复并通过真实慢读及 15 项互操作验证。网络/TCP 建连抖动另列未确定因素，不能归入此缺陷已修复范围。
