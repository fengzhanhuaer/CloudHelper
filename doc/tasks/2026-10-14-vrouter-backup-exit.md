- 任务标识：`2026-10-14-vrouter-backup-exit`
- 状态：`待发布（GitHub API 的 Fake IP 通路失败）`
- 创建时间：`2026-10-14 10:24 +08:00`
- 更新时间：`2026-10-14 11:05 +08:00`
- 用户原始需求：主控路由规则添加备用出口，主出口不可用时探针自动使用备用出口。
- 用户最新指令：主控路由页面仅在点击对应页签按钮时加载该页签数据，避免进入页面时一次性加载造成卡顿。
- 启用方式：明确长任务条件，跨主控配置、探针数据面、验证与发布。

## 一、需求定义

### 1.1 背景与问题

现有 `probe_exit` 路由规则只有 `exit_node_id`；探针按其规划路径，fake-IP 映射和出口校验也固定于该节点。主出口路径不可用时无法转到另一出口。

### 1.2 目标

主控可为每条探针出口规则配置一个备用出口；探针在主出口不可达时自动将新流量送往备用出口，主出口恢复后恢复优先使用主出口。

### 1.3 范围、非范围与约束

- 范围内：管理页、主控持久化/校验/下发、探针 TUN/fake-IP/代理选路与出口授权、回归测试。
- 范围外：改变已有直连/拒绝规则、自动升级已安装探针、把单一目标站点故障认定为整个出口故障。
- 约束：旧规则无备用出口时行为不变；主备不能相同；不能借备用出口绕过出口授权；不重写现有 fake IP。
- 页面约束：默认显示的页签可在首次进入时加载自身数据；其他页签仅在用户点击时发起对应请求。

## 二、总体架构

### 2.1 当前现状

主控 `route.html` -> `/mng/api/route/virtual_router/route_rules` -> `probeVirtualRouterRouteRule` -> 探针配置同步。探针通过规则或 fake-IP 项中的单一 `ExitNodeID` 选路径；`currentProbeVirtualRouterPathBetweenNodes` 会避开本地断开的 Carrier，出口处理再校验节点身份。

### 2.2 目标架构

规则添加可选 `backup_exit_node_id`。主控校验并下发；入口以主出口优先，主路径无本地 Carrier 或近期端到端 RTT 连续失败时选备用。存在备用规则时，入口限频异步探测主路径以发现多跳故障与恢复。fake-IP 地址及主出口映射保持不变，实际路径末端与域名规则共同证明备用出口授权。切换只影响新连接；现存 TUN 连接可能需要重连，代理连接按建立时所选路径保持。

### 2.3 关键模块与职责

| 模块 | 当前职责 | 目标职责 | 输入 | 输出 | 依赖 |
|---|---|---|---|---|---|
| 主控管理页/API | 编辑并校验单出口规则 | 增加备用出口输入、持久化与校验 | 规则 JSON | 同步配置 | 探针节点库 |
| 探针入口 | 选择单一目标节点 | 主备选路 | 规则、fake-IP、Carrier 状态 | 有效路径 | 拓扑、运行时 |
