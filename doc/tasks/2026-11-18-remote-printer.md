## 一、需求定义

REQ-001：本地电脑和 52.1 Wi-Fi 手机通过现有授权网关访问远程 192.168.50.122；验收为完整获取 SyncThru 页面，打印通信由手机用户验收。自动发现另需广播跨网段支持，不能以 TCP 端口可连接代替应用成功。范围不含修改打印机固件、放宽网关授权或建立全网广播桥。
REQ-002：插件自动保护所有经过 chvr0 的 IPv4 TCP 转发，双向 SYN/SYN-ACK MSS 上限 1360（MTU 1400），不提高较小 MSS；启动、修复、停止管理自有规则，不重置已有连接。
REQ-003：核对 Probe 与安卓实现，避免将路由器系统规则照搬到独立用户态 TCP 协议栈；验证后通过正式工作流发布。

## 二、总体架构

本机 Windows Probe / 本地 52.1 路由器 → 虚拟链路 → 51.1 网关（WAN 192.168.50.51）→ 打印机。51.1 本地 curl 完整返回 HTTP 200 / 2152 字节，本机跨链路初始仅收到 17 字节后超时；定向 MSS 1360 后主文件恢复。chvr0 MTU 1400，包解析拒绝 IPv4 分片；通用规则需在发往物理端点前降低 TCP 广告 MSS，避免后续响应跨 TUN 需要分片。

接口记录：暂不新增接口；先检查现有 TCP/IPv4 转发。

## 三、单元设计

UNIT-002：/jffs/scripts/cloudhelper-printer-mss.sh。用 iptables -C 检查后才添加，避免重复；nat-start 与 services-start 各追加一条调用，保留原内容。只在配置安装时写 JFFS，运行时不写。暂不改插件源码。
UNIT-003：26 节点 gateway_proxy.allowed_node_ids。通过 Unix 管理接口 configure 局部保存，保留现有 9、14，仅添加现场确认的 25（52.1）；现有 CIDR 不改变。现有接口 IF-001：status 读取 CSRF 后 configure 保存 gateway_proxy，CSRF 仅在进程内使用，不记录。
UNIT-004：platform.c / platform_address.h 共用 CHVR_MSS 规则描述，启动幂等安装，健康检查核对规则与两个 FORWARD 钩子，已有 repair 仅补缺失项，停止精确删除自有链。仅 IPv4 数据面，既有 IPv6 WAN 承载保持原状。
UNIT-005：test_platform_command.c 与有界 kernel MSS 测试；验证错误检查延期、幂等、双向 MSS/checksum、较小 MSS、非 SYN/非隧道隔离、修复与卸载。
