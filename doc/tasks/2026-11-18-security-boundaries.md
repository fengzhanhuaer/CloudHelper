## 二、总体架构

主控普通 HTTP 监听经代理提供认证和管理；独立 TLS 入口仅开放 Probe 白名单。节点控制流为 WebSocket 上的 yamux JSON 值流，不能改成只接受逐行 JSON。远程控制台由主控代理已认证节点响应，必须与管理浏览器权限隔离。

目标：在共享控制台响应头边界无条件隔离；在公开认证解码前施加小额预算；在控制流 JSON 解码前施加逐消息预算并扣除解码器预读。保留 HMAC、票据、原厂 HTTPD 认证及管理会话控制。

## 七、决策与冲突记录

- DEC-001：无条件设置桥接 CSP；不以节点可控的 MIME 作为权限边界，保留正常脚本和 opaque-origin API 访问。
- DEC-002：控制流保留 JSON 值流语义；既有 Go 编码器及 C 插件均兼容，不要求客户端升级协议。
- DEC-003：控制流上限 16 MiB，依据现有 8 MiB 控制台/订阅响应经 base64 后约 11 MiB；不能简单设为普通报告的小上限。
- DEC-004：消息开始后设置完成期限，正常空闲报告间隔不设新限制；安全修复不得重新引入反复重连。
- DEC-005：按 release skill 验证后自动提交推送；生产二进制仅走产品在线升级，不在本任务手动部署。
- DEC-006：安全扫描与修复报告分离；完成的两个扫描集合不可改写。追加发现均需合法节点身份，不认定匿名公网 RCE。
- DEC-007：使用本机 WSL UbuntuServer 验证 C；系统 libcurl 的旧接口弃用警告仅在本地构建参数中豁免，不修改兼容路由固件的源码接口。
- DEC-008：本机生成的返程同样按整条路径选择授权 owner；精确匹配已认证入站路径的反向缓存时可复用授权，不额外保存缓存或写 JFFS。有效 A 出口不可用时不能借用未授权的 B 出口。
- DEC-009：用户明确选择按当前工作流发布。已从 018210eb4 证实 Docker / Linux Router ARM64 的移除属主动裁剪，并核对 v0.4.123 的 10 个资产；使用匹配当前工作流的临时预检清单，不修改用户级技能或仓库工作流。其他分支、远端、Git 操作状态、版本、CLI 认证、Actions 和 release 读取检查均保留且通过。
